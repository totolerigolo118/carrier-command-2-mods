## Ce que le SDK ajoute à l'intérieur du jeu : l'interface Lua (nouveauté 0.5.0)

Dès que `dinput8.dll` est présent, **tous les scripts Lua du jeu** (donc ceux de n'importe quel mod) reçoivent une table globale `cc2x` : lecture de tous les véhicules (copie à chaque tick) et **commandes** mises en file pour le tick suivant : changer des champs de véhicule ou d'aérodrome (liste blanche : 13 champs de véhicule et 4 d'aérodrome, `lua_world.c:726-736`), waypoints, position / vitesse / rotation d'un corps physique, **freins et train**, demande d'atterrissage, files d'aérodrome, tir de rayon, règles de décision (contrôleurs d'îles, apparitions, hangar). **Aucune** fonction de fichier, de processus ou de réseau n'y figure (`lua_world.c:850-859` : 25 fonctions, toutes sur le monde du jeu, plus `has` et `log` de `cc2x.c:598-628`) ; `cc2x.log(...)` écrit une ligne de texte (≤ 900 caractères) dans `cc2x.log`. Les id invalides sont ignorés (`find` rend NULL) ; indices vérifiés dans `world.c:173-231`. Donc : un mod malveillant pourrait **tricher dans la partie** (téléporter des avions, etc.), pas toucher à ton ordinateur via cette interface.

## Les 4 conditions

1. **Compiler le commit figé tel quel**, depuis une copie hors du clone, **uniquement `dinput8.dll`** (pas les exemples ni le test : `build.py` les construit aussi ; en plus, `library_custom_7.lua` et `library_custom_9.lua` des exemples **écraseraient nos scripts SIM et SORTIES** du mod `cc2_mesures` : ne **jamais** installer `examples/lua_air_traffic` ni `tests/lua_mod`). Après compilation : relire la **table d'imports** de la DLL (attendu : `KERNEL32` et la bibliothèque C ; **aucun** `ws2_32 / wininet / winhttp / advapi32`).
2. **Rien d'autre dans les dossiers que le chargeur lit** : aucun mod avec dossier `cc2x`, pas d'autre `dinput8.dll`. Contrôle à refaire avant chaque pose.
3. **Surveiller la charge** : en 0.5.0 le SDK copie **tous** les véhicules, îles et aérodromes **à chaque tick** (`lua_world.c:433-453` ; la 0.4.0 le faisait « tous les quelques ticks », `cc2x.h` ligne 259 modifiée), **même si personne ne s'en sert**. Ta tour a déjà un fil de simulation saturé (SIM ×1,33 à 100 % d'un cœur) : mesurer l'affichage SIM avant / après ; si ça baisse, le retrait est immédiat (retirer la DLL) et on peut envisager une version locale sans ce rappel, **sur ta décision**.
4. **Un accord séparé pour chaque pose** (étape 4) et pour chaque lancement du jeu ; **sauvegarde jetable** ; retour arrière = supprimer `dinput8.dll` (et le plugin) ; l'exécutable patché n'est pas concerné.

## Autres réserves (honnêtes)

- **Relecture humaine, pas un audit** : une seule lecture, du texte seulement. Elle n'exclut pas un bogue de mémoire (le SDK manipule les structures internes du jeu par décalages fixes ; seuls les 7 débuts de fonctions et les 3 cases de table sont vérifiés au démarrage, pas les décalages d'objets). Une erreur ferait **planter le jeu**, pas fuiter des données.
- **Jeune projet** : 13 commits en 2 jours, un auteur principal (`dioramawork`) et une fusion par un second compte (`kodiak`) ; la page du mod Island Airfields renvoie vers ce dépôt (provenance cohérente, déjà notée au journal de la tour). Licence **GPL-3.0-or-later** : un plugin compilé avec `cc2x.h` est lui aussi sous GPL **dès qu'on le distribue** ; pour un usage privé dans notre dépôt privé, aucune obligation.
- **Robustesse au démarrage** : `DllMain` fait lui-même `LoadLibrary` et des écritures de fichier (`cc2x.c:895-911`) alors que sa propre documentation le déconseille aux plugins ; ça marche chez l'auteur, mais c'est un risque de blocage au lancement (retour arrière : supprimer la DLL).
- **Cohérence avec nos patchs de l'exécutable** : l'exécutable actuel (`8E7FCBB6…E8BE`, `ascenseur_x2` + `temps_x2`) a le même horodatage PE (`0x6a36c177`) et la même taille d'image (`0x00af7000`) que le SDK attend, **7 sites de contrôle sur 7 conformes** et les 3 cases de table intactes ; **aucune adresse citée par le SDK n'est à moins de 125 861 octets d'un de nos 33 changements**. Le SDK accrochera la même fonction de tick (`0x0077ee10`) que celle où `temps_x2` lit son facteur : compatible sur le papier (les crochets passent par la table de fonctions, pas par le code), **à confirmer par l'affichage SIM**.

## Ce que cette relecture apporte en plus (pour la voie « sans tiers »)

Le SDK publie des **décalages Windows 32 bits** de l'objet véhicule (roues `+0xac` pas `0x70`, contact = premier flottant de chaque roue, état de vol `+0x170`, état d'accostage `+0x174`, rattaché `+0x10c`, mode de contrôle `+0x1d0`, fonctions virtuelles frein / train aux cases `0x94` / `0x98`). Ce sont des **faits sur le jeu**, pas du code ; s'il faut un jour la voie « nos propres crochets » (plan B du Mac), ils serviront de repères **à revérifier nous-mêmes au désassembleur** avant toute écriture.
